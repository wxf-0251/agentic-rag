workflow.py — Nodes & Edges

  graph = StateGraph(AgentState)

  # === Nodes ===
  graph.add_node("planner", planner_node)           # decompose query → outline
  graph.add_node("researcher", researcher_node)      # parallel retrieval
  graph.add_node("writer", writer_node)              # synthesize section
  graph.add_node("reviewer", reviewer_node)          # quality gate

  # === Edges ===
  graph.set_entry_point("planner")                   # START → planner
  graph.add_edge("planner", "researcher")            # planner → researcher

  # Parallel fan-out: 1 researcher per sub-question
  graph.add_conditional_edges("researcher", router, {
      "writer": "writer",       # all questions done → writer
      "researcher": "researcher" # more questions remain → loop
  })

  graph.add_edge("writer", "reviewer")                # writer → reviewer

  # THE KEY LOOP: reviewer decides next step
  graph.add_conditional_edges("reviewer", review_gate, {
      "writer": "writer",         # PASS this section → write next
      "researcher": "researcher", # FAIL → re-search with refined query
      "end": END                  # all sections done → finish
  })

  graph.compile(checkpointer=MemorySaver())

Data Flow — One Complete Research Cycle

Step-by-step state transformation
1. planner_node
query → sub_questions (5 items) + outline (4 chapters)
Sets state.current_section_idx = 0
2. researcher_node (invoked N times via Send API)
For each sub_question → router picks Tavily/Chroma/YFinance
Results accumulated in state.research_results, state.citations
3. writer_node
reads outline[current_section] + all research → drafts section
Appends to state.completed_sections
4. reviewer_node
Checks: citation coverage, data consistency, logic gaps
→ PASS: current_section_idx += 1, go to writer for next section
→ FAIL: append refined queries, state.search_iteration += 1, go to researcher
5. Terminal condition
All sections PASS review AND current_section_idx >= len(outline) → END

Router Logic — Per Sub-Question Data Source

How the researcher picks its tool
Question Type Example Tool
latest_news "2025-2026 人形机器人融资事件" Tavily Search
technical_concept "谐波减速器 vs RV 减速器原理" Chroma DB
financial_data "特斯拉近一年股价走势" Yahoo Finance
mixed "核心零部件供应商竞争格局" Tavily + Chroma (merge)

Router is a lightweight LLM call (Haiku) that classifies the sub-question type. Planner sets initial type; Researcher can override if needed.
