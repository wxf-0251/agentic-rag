Design: Error Handling & Edge Cases

Graceful degradation, not crash-and-burn

Failure Modes & Recovery Strategies

What can go wrong at each stage
Failure Recovery UX
Tavily API rate limit / timeout Exponential backoff (1s→2s→4s), max 3 retries. If all fail: fallback to Chroma local search Research card shows "Retrying..." → "Using local backup"
Yahoo Finance: symbol not found / no data Return empty result with error metadata. Writer skips chart, notes "data unavailable" Inline note: "Financial data temporarily unavailable"
Chroma DB empty / no relevant docs Auto-escalate to Tavily search for that sub-question "No local results → searching web..."
Reviewer rejects section 3+ times max_iterations=3 safety cap. After 3rd fail: accept with caveat flag Yellow banner: "This section has limited source coverage"
LLM API error (5xx, rate limit) Retry with exponential backoff. If persistent: save partial state, offer resume "Service interruption — partial report saved"
Query is too vague / unresearchable Planner detects vagueness → asks clarifying questions via UI before proceeding Chat-style clarification prompt in sidebar

Safety Limits

Preventing runaway loops and cost explosions
Loop Breakers
  • max_iterations = 3 (per section)
  • max_sub_questions = 7
  • max_total_time = 300s (5 min)
  • max_tokens_per_section = 4000
Cost Guards
  • Prompt Caching on planner/writer/reviewer prompts
  • Haiku for all researcher work (cheap)
  • Estimated cost per report: ~$0.50-1.50
  • Configurable max_budget in config.py
