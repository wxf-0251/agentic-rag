3 Implementation Approaches

Same core design, different abstraction levels

A

LangGraph + Custom Agents (推荐)

StateGraph 编排 + 手写 Agent Node + Anthropic SDK 直接调用

Pros

  • 每个 Agent 行为完全可控，Prompt 精细调优
  • LangGraph 内置 checkpoint/streaming/重试
  • Reviewer→Re-search 循环自然映射到条件边
  • 工业级可扩展（加 Agent 只需加 Node）

Cons

  • 代码量最多 (~1500 LOC)
  • 需要理解 LangGraph 概念 (StateGraph, ConditionalEdges, Send API)
B

LangChain + CrewAI Hybrid

CrewAI 角色化 Agent 定义 + LangChain RetrievalQA 链路

Pros

  • Agent 角色定义快（Planner/Researcher/Writer 有现成模板）
  • LangChain 生态工具链成熟

Cons

  • Reviewer→Re-search 循环在 CrewAI 里是 hack
  • 流式输出很难控制粒度
  • 框架黑盒调试困难
  • CrewAI 底层也是 LangGraph，多一层抽象
C

Pure Anthropic SDK + 手写 Loop

最小依赖，手动实现 Agent While-Loop + Tool Use

Pros

  • 零框架依赖，完全透明
  • 代码量最少启动快

Cons

  • 手动实现状态管理/并行/重试——你最终会写出半个 LangGraph
  • 流式输出需要自己写 SSE/WebSocket
  • 扩展性差，加新 Agent 要改动核心 loop

推荐 A：LangGraph 的 StateGraph + ConditionalEdges 天然匹配你的 "循环反思 (Reasoning Loop)" 需求——Reviewer 不通过就回到 Researcher，这正是 LangGraph 条件边的设计初衷。手写 Agent Node 保证每个 Agent 的 Prompt 质量，比 CrewAI 的黑盒模板强得多。
