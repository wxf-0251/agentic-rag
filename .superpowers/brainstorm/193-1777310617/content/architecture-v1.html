System Architecture Overview

4-Agent Agentic RAG with LangGraph Orchestration & Loop Reasoning

Core Flow — 4-Stage Reasoning Loop

Agentic RAG Pipeline
🧠 Stage 1: Planner Agent (Opus 4)
Input: "分析2026年人形机器人核心供应链及投资风险"
→ Query Decomposition (拆成 5-7 个子问题)
→ Report Outline Generation (章节大纲)
→ Task Dispatch → Researcher Agents
🔍 Stage 2: Researcher Agents (Haiku 4 × N parallel)
Router decides per sub-question:
• "最新融资动态" → Tavily Search API
• "谐波减速器技术原理" → Chroma Vector DB
• "特斯拉/三花股价走势" → Yahoo Finance API
→ Retrieved context + sources stored in shared state
✍️ Stage 3: Writer + Reviewer Loop (Opus 4)
Writer synthesizes → Reviewer critiques:
• "是否有足够引用支撑？"
• "数据是否一致？"
• "结论是否有逻辑漏洞？"
→ If FAIL: triggers re-search with refined keywords
→ If PASS: final report generated
📄 Stage 4: Streaming Output via Streamlit
Real-time streaming: outline → research progress → draft sections → final report
Markdown + Citations + Auto-generated Charts (matplotlib)

LangGraph State Machine

Agent State Graph
[START] user_query
↓
planner_node: decompose → outline → dispatch
↓
researcher_1
researcher_2
researcher_N
parallel execution (Send API)
↓
writer_node: synthesize section
↓
reviewer_node: check quality
↓ ↖ (loop: re-search if fail)
[END] final_report

Key Design Principles

  • Not a linear pipeline — Reviewer can trigger re-search, creating reasoning loops
  • Router decides data source — per sub-question, not one-size-fits-all retrieval
  • Shared state via LangGraph StateGraph — all agents read/write to typed state
  • Streaming at every stage — user sees progress in real-time, not a 3-min spinner
